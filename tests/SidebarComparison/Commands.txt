CONFIGURATION
------------------------------------------------------------
config/sites/NVRCP.js  Existing six products and their credentials.
config/sites/DPBH.js   Products 1-6; URL A/B supplied; credentials blank.
config/sites/TXOCA.js  Products 1-6; URL A/B supplied; credentials blank.
config/sites/NJ.js     Products 1-4; URL A/B supplied; credentials blank.
config/sites/SAPTA.js  Products 1-3; URL A/B supplied; credentials blank.

Fill username/password for BOTH sides before running a new site.
--list works with blank credentials and makes no login attempts.
It prints each resolved URL, effective version and GLOBAL, SITE or PRODUCT version source.
No credentials are copied between sites or between URL A and URL B.

config/runSettings.json:
  sites: ["NVRCP"]       Default sites when --site is omitted.
  products: []           Default: enabled products in selected sites.
  products: [1, 3]       Alternative: selected product ids in each site.
  products: ["ALL"]      Alternative: all enabled products.
  parallelWorkers: 3    Workers used by --parallel without a number.
  workers: 3            Default Playwright workers.
  fullyParallel: true  Allow independent comparisons to run together.
  headless: true        Default browser visibility.
  navigationRetries: 1 Retry the initial login-page GET once on a transient
                       network error or navigation timeout. Set 0 to disable.
  sidebarStableMs: 1000 Capture only after menu content is unchanged for this
                        many milliseconds and visible loading indicators finish.
  retainSessionTraceOnFailure: true Keep URL A/B traces on the first failure.

Precedence: command options > environment variables > runSettings.json.
Environment variables: SITES, PRODUCTS, WORKERS, SIDEBAR_HEADED.
SIDEBAR_HEADED=true shows browsers; false runs headless.

PARALLEL EXECUTION
------------------------------------------------------------
npm run sidebar -- --site=ALL --product=ALL --parallel 4
npm run sidebar -- --site=ALL --product=ALL --parallel=5
npm run sidebar -- --site=ALL --product=ALL --parallel 5
npm run sidebar -- --site=ALL --product=ALL --parallel=5 --headed
Four workers may open eight isolated browser sessions (URL A and URL B per test).
Five workers may open ten isolated sessions. No four-worker cap is applied.
An explicit --parallel value overrides the defaults; workers and parallelWorkers
in runSettings.json remain unchanged unless you edit them yourself.
Login waits for editable fields and any required business-unit selection.
Sidebar capture waits for loading to finish and menu items to stabilize.
Login clicks are submitted once; invalid credentials and HTTP errors are not
hidden by whole-test retries. Failure screenshots and per-side traces are
attached to the Playwright report, including when retries are disabled.
The practical worker limit still depends on available RAM/CPU and server capacity.

VERSION OVERRIDES (EXISTING COMMANDS STAY THE SAME)
------------------------------------------------------------
Version precedence for each side: GLOBAL > SITE > PRODUCT.

1. Product-wise URLs (default)
   Keep globalVersionOverrides and all siteVersionOverrides disabled.
   Each selected product uses its existing urlA.loginUrl and urlB.loginUrl.

2. Site-wise versions
   In config/sites/<SITE>.js, add/edit CONFIG.siteVersionOverrides:
   siteVersionOverrides: {
     enabled: true,
     versionA: '11.3.25.03',
     versionB: '11.4.42.03',
   },
   These versions apply to the selected enabled products within that site.
   Set globalVersionOverrides.enabled to false to use site versions directly.
   Other sites continue using their own site versions or product URLs.

3. Global versions
   In config/runSettings.json, add/edit:
   "globalVersionOverrides": {
     "enabled": true,
     "versionA": "11.3.25.03",
     "versionB": "11.4.42.03"
   }
   These versions apply to all selected enabled products across selected sites.
   Use --site=ALL --product=ALL to select all discovered sites' enabled products.
   Each product keeps its own site, server, HTTP/HTTPS and login page.

Only the four-part version at the end of the ALiS application folder changes:
Before: http://172.16.3.2/ALiSNVRCP2TESTING11.4.42.01/LoginRadiation.aspx
After:  http://172.16.3.2/ALiSNVRCP2TESTING11.4.42.03/LoginRadiation.aspx
The IP address, port, login path, query string and fragment are preserved.

Each side resolves independently. A blank versionA or versionB falls back
to the next level. Both versions may be equal for a same-version comparison;
the URLs are identical only when the products' remaining URL parts also match.
An enabled override needs at least one populated version. Use four numeric
parts such as 11.4.42.03; leading zeroes are preserved. Do not enter full URLs
in version fields. Invalid active overrides fail before browsers open.
Disabled override values are ignored.

Every selected enabled product still needs complete urlA.loginUrl and
urlB.loginUrl base URLs without embedded credentials. Active version overrides
require exactly one version at the end of an ALiS application folder in each
affected base URL. Missing or ambiguous folder versions give a clear error.
Credentials, labels, login controls and business unit selections remain
product-specific. Disabling overrides restores the original product URLs.
Only selected sites with enabled selections validate overrides. New site
files may omit siteVersionOverrides and use product/global versions normally.
The former globalUrlOverrides/siteUrlOverrides objects are replaced by the
version objects above; obsolete objects give migration guidance.
Reports show the resolved URLs; Playwright annotations and JSON also include
the effective versions and their GLOBAL, SITE or PRODUCT sources.

The SAME commands work for all three modes:
npm run sidebar -- --site=NVRCP --product=ALL --parallel 3
npm run sidebar -- --site=NVRCP,NJ --product=ALL --parallel 3
npm run sidebar -- --site=ALL --product=ALL --parallel 3

Preview the selected URLs, versions and sources without logging in:
npm run sidebar -- --site=ALL --product=ALL --list
npm run sidebar -- --site=NVRCP,NJ --product=1,2 --list
--list preserves the latest reports and never prints credentials.

OPTIONS
------------------------------------------------------------
--site=NVRCP            One site (case-insensitive).
--site=NVRCP,DPBH       Multiple sites.
--site=ALL              All discovered sites.
--product=1             Product id 1 in EACH selected site.
--product=1,3,6         Selected ids in EACH selected site.
--product=ALL           All enabled products in the selected sites.
--headed                Show browsers.
--headless              Hide browsers, overriding runSettings.
--project=chromium      Current configured browser project.
--parallel 3            Up to 3 comparison tests at once.
--parallel=3            Same as above.
--parallel=5            Up to 5 comparisons (10 URL sessions) at once.
--parallel              Use runSettings.parallelWorkers.
--list                  Preview selected tests without opening browsers.

Each comparison opens two isolated sessions: URL A and URL B.
Workers limit comparison tests, not the number of browser pages.
Product ids remain stable when names or array order change.
enabled:false products are skipped, even with ALL or explicit product ids.
Set enabled:true to include a product; omitted enabled defaults to true.
Disabled products do not require URLs or credentials to be filled.
Sites with no enabled selections are skipped while other sites continue.
If no enabled products remain in the entire selection, the run stops clearly.
Enabled products must have valid resolved URLs and both sides' credentials.
Without --product, runSettings.products applies; [] uses enabled products.
A requested id must exist in EVERY selected site; invalid selections fail.
ALL must be used alone, not combined with individual ids or site names.

ADDING MORE PRODUCTS
------------------------------------------------------------
1. Open the appropriate config/sites/<SITE>.js file.
2. Copy one product object in the array returned by getProductComparisons().
3. Assign a new, unique positive integer id (for example 7).
4. Edit its name and both sides' URLs, credentials and labels.
5. Preview with --site=<SITE> --product=ALL --list.
6. Run by id. Renaming or reordering existing products does not change ids.
There is no fixed six-product limit.

ADDING MORE SITES
------------------------------------------------------------
1. Copy config/sites/DPBH.js to config/sites/NEW_SITE.js.
2. Set CONFIG.site to 'NEW_SITE' (matching the filename).
3. Edit all products and both sides' URLs and credentials.
4. Run: npm run sidebar -- --site=NEW_SITE --product=ALL --list
5. Fill credentials, then remove --list to execute.
Discovery is automatic; no registry or runner code change is needed.
Use letters, digits, underscores or hyphens, starting with a letter.
Names beginning with "_" are ignored, suitable for inactive templates.
config/comparisonConfig.js handles discovery, selection and validation.
The config/sites/ folder contains only editable site configurations.
Do not leave backup .js files in this folder: every site file is loaded.

OPTIONAL BUSINESS UNIT SELECTION
------------------------------------------------------------
Business unit settings are in config/runSettings.json, not the site files.
Use the uppercase site code, stable product id and URL side:

"businessUnits": {
  "NVRCP": {
    "1": { "urlA": "", "urlB": "" }
  },
  "DPBH": {
    "1": { "urlA": "", "urlB": "" }
  }
}

Replace a blank with the dropdown option value as a string, not its label.
Add other product ids or sites only when a specific selection is needed.
URL A and URL B can have different business unit values.
Blank, omitted or null values use the existing automatic selection:
if the popup appears, select its first option with a nonempty value.
If no business unit popup appears, no selection is performed.
Product names or array order can change without changing these id-based settings.

LOGIN AND REPORTS
------------------------------------------------------------
CONFIG.login defines each site's login field/button names.
For different login labels on URL B, add a login object inside urlB.
Partial per-URL overrides inherit the remaining site's login settings.
Both URLs independently detect Angular or ASP.NET sidebars.
HTTP errors such as 404/500 fail immediately with the URL and status.
Initial page-load retries do not retry HTTP errors or login submissions.

One consolidated HTML report and one Excel workbook are written after
ALL selected comparisons finish, for both single-site and multiple-site runs.
No individual product HTML reports or workbooks are generated.

Playwright test report: playwright-report/index.html (built-in HTML reporter)
Comparison HTML: comparison-report/index.html
Excel: comparison-report/sidebar-comparison.xlsx
Data: comparison-report/summary.json (current-run consolidated results)

The native Playwright test report and comparison HTML report each open once
after all reporters finish, for passed and failed runs. Their auto-open settings
are independent. Open a test in Playwright and expand Attachments for the clickable
HTML Comparison Report and Excel Comparison Report links. Both contain the
complete run, including all selected sites/products. The HTML attachment's
Download Excel Report link also works when served by Playwright. Share the
whole playwright-report folder, including data/, to keep attachments available.
Playwright test steps, errors, screenshots and other attachments use the normal
Playwright report interface. No custom recreation of that interface is used.

The comparison HTML title is "Sidebar Comparison Report". Results are grouped by site,
with site/status filters and search. Overall/product DIFFERENCES badges are
not displayed; summary counts and comparison categories remain unchanged.
Expand a product to see both URLs, item counts, comparison categories and errors.
The Excel workbook keeps Run Summary, Comparisons and Execution Errors, with
four separate detail sheets: Missing-Text Mismatch, Icon Mismatch,
Extra in URL B and Matched Text. Excel does not allow '/' in worksheet names.
The Missing-Text Mismatch sheet heading is "Missing/Text Mismatch".
Comparisons does not include a Comparison Result column. The Run Summary
retains the recorded outcome counts without adding a hidden status column.
Each detail sheet groups results by site/product, using the same four columns
as HTML: URL A item, URL B item, URL A icon, URL B icon.
Populated detail tables have their own column filters. Empty categories and
unavailable comparisons are shown explicitly. Matched Text includes items with
matching text, even when their icons differ. Each URL's menu item and icon are
shown in separate side-by-side columns. Category labels appear in the relevant
report section. Icon differences remain listed in Icon Mismatch. The HTML download link is
labeled "Download Excel Report".
MATCHED means both text and icons match; DIFFERENCES means comparison found
menu changes; ERROR means a runtime failure; SKIPPED/NOT RUN remain explicit.
Runtime failures before login and retries are included. Only the final attempt
counts toward totals; earlier attempts remain available in error/history detail.
Browser project and repeat labels/columns are omitted from comparison HTML and Excel.
The native Playwright report keeps its standard project and retry information.
Their internal identifiers still keep separate executions from overwriting
each other. Repeated comparisons are retained, not silently deduplicated.
Reports only contain tests selected for the current run; older files are not scanned.
--list does not generate or replace reports.

runSettings.json:
  openHtmlReport: true   Open the comparison HTML report once at run end.
  openPlaywrightReport: true Open the native Playwright test report once at run end.
  openExcelReport: false Open the workbook once when changed to true.
  attachReports: true   Attach HTML, Excel, JSON and text comparison reports.
  attachReports: false Do not attach comparison reports to the Playwright report.
HTML and Excel reports are still generated with either setting; auto-open is
controlled separately. Comparison data remains internal for aggregation.
Screenshots, videos, traces and stdout/stderr are Playwright diagnostics and
are not controlled by attachReports. Changes apply to newly generated reports,
not reports from earlier runs. Set true again to restore the report links.
PLAYWRIGHT_HTML_OPEN=never disables automatic HTML opening for unattended runs.
CI runs generate all reports without opening a browser. --list opens nothing.
Automatic opening and npm run report both use Playwright show-report with an
available port. An older report using port 9323 will not block the next run.
The terminal prints the report URL after the server is ready. Startup errors
are shown as warnings instead of being hidden. Each enabled report opens once.
If the previous workbook is locked in Excel, the new workbook gets a timestamp
suffix and the HTML download link points to that current-run workbook.

npm run report

REPORTING VERIFICATION (NO SITE LOGIN)
------------------------------------------------------------
npm run test:reports
Checks native report generation, HTML/Excel attachment links, retries, failures,
skipped tests, auto-open preferences and preservation of reports during --list.
Uses temporary files and does not replace the latest framework reports.

VERSION RESOLUTION AND BROWSER SMOKE VERIFICATION (NO REAL SITE LOGIN)
------------------------------------------------------------
npm run test:urls
Checks product, site and global version precedence, partial fallbacks, invalid
versions, disabled products, automatic site discovery and --list output.
Checks that only the ALiS folder version changes, preserving IPs, protocols,
ports, login paths, query strings, credentials and leading zeroes.
Also checks bounded navigation retries and immediate HTTP error diagnostics.
Browser smoke scenarios exercise isolated logins, ASP.NET/Angular sidebars and
consolidated/native reporting using local fixture pages and temporary reports.
The browser suite runs at both four and five workers with delayed business-unit
modals and lazy menu items, and verifies first-failure traces and no login replay.
It also checks both five-worker command formats, headed/headless option parsing
and precedence over configured defaults. Real-site commands use the same runner.

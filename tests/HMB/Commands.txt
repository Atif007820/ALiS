Setup
-----
npm install
npm run browsers:install


List Tests
----------
npm run hmb:list


Run Register Only
-----------------
npm run test -- --spec=register --headed
npm run test -- --spec=01_RegisterUser.spec.js


Run Login Apply Only
--------------------
npm run test -- --spec=apply --headed
npm run test -- --spec=02_LoginApply.spec.js --project=chromium

Set both loginName and password in:
  config\standaloneLoginCredentials.js
To use an account from a standalone registration, copy both credentials from
the project-specific user file, for example testData\lastRegisteredHmbUser.chromium.json.


Run Approval Only for an Already Submitted Application
------------------------------------------------------
Set the exact transaction number in:
  config\approvalTransacNumber.js -> TransactionNumber

Approver credentials are configured in:
  config\approvalTransacNumber.js

Run Script 3 by itself:
  npm run test -- --spec=approve --headed
  npm run test -- --spec=03_ApproveApplication.spec.js --project=chromium


Run Full E2E
------------
npm run hmb

Show the browser during the full flow:
npm run hmb -- --headed

The default is headless=true in config\runSettings.json.

This runs Register, Login/Apply, and Approve as separate Playwright scripts in
strict serial order for each selected browser project:
  01_RegisterUser.spec.js -> 02_LoginApply.spec.js -> 03_ApproveApplication.spec.js

Login/Apply uses the account created by Register for the current run. Approve
uses the transaction number captured and printed by Login/Apply. Both handoffs
are scoped to the current run, browser, and repeat. A missing or mismatched
handoff stops the flow.

Execution Time
--------------
HMB uses the TEST application only. Use --project=chromium or --project=msedge
to select a browser. The runner controls workers so the flow completes serially.
Keep slowMo: 0 in config\runSettings.json for normal-speed execution.
The Playwright report shows timings for each Login Apply section, including
personnel, mandatory documents, submission, and payment.

Config Files
------------
URLs and run behavior:
  config\urls.js
  config\runSettings.json
  config\standaloneLoginCredentials.js
  config\approvalTransacNumber.js

Payment recovery:
  paymentReadyTimeoutMs controls how long to wait for the payment action.
  paymentApiRetries controls retries after transient GetApplicationFee errors.
  paymentRetryDelayMs sets the initial retry pause, which grows exponentially.
  paymentRetryMaxDelayMs caps the backoff and Retry-After delay.

Navigation recovery:
  navigationRetries controls retries for transient connection failures.
  navigationRetryDelayMs sets the initial pause; navigationRetryMaxDelayMs caps it.

Fixtures:
  fixtures\hmb.fixture.js

Hardcoded test data:
  config\editableData.js

Generated random data:
  utils\randomData.js
  utils\hmbDataFactory.js

Last registered user:
  testData\lastRegisteredHmbUser.json

Upload documents:
  Documents\*.doc
  Documents\*.docx
  Documents\*.pdf
  Documents\*.rtf
  Documents\*.txt

Document upload behavior:
  The framework randomly selects an upload file from the Documents folder for
  every personnel and mandatory document upload. Add future upload samples to
  Documents; no script change is needed.

Setup
-----
npm install

Main Commands
-------------
Run npm run hmb from the workspace root or the HMB framework folder.

Register -> Apply -> Approve (also the default for npm run hmb):
  npm run hmb -- --user=new
Existing applicant -> Apply -> Approve:
  npm run hmb -- --user=existing
Existing applicant -> Apply only:
  npm run hmb -- --apply
Register -> Apply only:
  npm run hmb -- --regapply
Approve an already submitted transaction:
  npm run hmb -- --approve
Register only:
  npm run hmb -- --reg

Account and Transaction Inputs
------------------------------
Use config\LoginCredentials.js for an existing applicant, or supply both
flags after npm's -- separator to override that file for one run:
  npm run hmb -- --user=existing --LoginName=ExampleUser --password='ExamplePassword' --list
  npm run hmb -- --apply --LoginName=ExampleUser --password='ExamplePassword' --list
Do not combine flow modes. Registering flows always use the newly created
account. Prefer the config file for real passwords, since npm and your shell
may echo or retain arguments.

With --approve, set TransactionNumber in config\approvalTransacNumber.js.
Approver credentials are separate and come from the same approval config.
To override the transaction for one run (example; remove --list to approve):
  npm run hmb -- --approve --TransacNum=2733 --list
The legacy --transaction and --transaction-number flags still work.
When a flow includes both Apply and Approve, only the transaction captured
in that run is approved. Account and transaction handoffs are scoped to the
current run, project, and repeat.

Preview and Reports
-------------------
Append --list to any mode to check command selection without logging in or
submitting anything:
  npm run hmb -- --regapply --list
  npm run hmb:list
  npm run report

Legacy shortcuts (from the HMB framework folder):
  npm run hmb:e2e
  npm run hmb:headed
  npm run hmb:e2e:headed
  npm run hmb:register
  npm run hmb:apply
  npm run hmb:approve
  npm run test -- --spec=register
  npm run test -- --spec=apply
  npm run test -- --spec=approve

Execution Time
--------------
HMB uses the TEST application only. Use --project=chromium or --project=msedge
to select a browser. The runner controls workers so the flow completes serially.
Keep slowMo: 0 in config\runSettings.json for normal-speed execution.
The Playwright report shows timings for each Login Apply section, including
personnel, mandatory documents, submission, and payment.

Config Files
------------
URLs and run behavior:
  config\urls.js
  config\runSettings.json
  config\LoginCredentials.js
  config\approvalTransacNumber.js

Payment recovery:
  paymentReadyTimeoutMs controls how long to wait for the payment action.
  paymentApiRetries controls retries after transient GetApplicationFee errors (8 retries / 9 total attempts by default; bounded at 10 retries).
  paymentRetryDelayMs sets the initial retry pause, which grows exponentially.
  paymentRetryMaxDelayMs caps the backoff and Retry-After delay.
  paymentRetryJitterMs adds a small random pause to spread concurrent retries.

Navigation recovery:
  navigationRetries controls retries for transient connection failures.
  navigationRetryDelayMs sets the initial pause; navigationRetryMaxDelayMs caps it.

LNI Conveyance E2E Playwright Framework - Commands
==================================================

Recommended run location:
  C:\Users\mohd.jamal\Downloads\Playwright

You can also run from:
  C:\Users\mohd.jamal\Downloads\Playwright\tests\LNI\Conveyance

When you run "npm run conv", the framework runs all three scripts in serial order:
  01_RegisterUser.spec.js -> 02_LoginApply.spec.js -> 03_ApproveApplication.spec.js

Approval credentials are required before a non-list run containing 03 starts.
Set both CONVEYANCE_APPROVER_LOGIN_NAME and CONVEYANCE_APPROVER_PASSWORD, or set
the matching environment-specific pair (for example, *_TEST). Environment-specific
credentials take precedence. Keep credentials in environment/local configuration, not commands.

Each environment/license/project/repeat executes its own complete serial flow.
02 passes its exact confirmed transaction to 03 using a fresh, isolated run file.
The handoff verifies run ID, environment, license, URL, project and repeat; it never
falls back to a previous run's transaction. --repeat-each repeats the complete flow.
Apply/approve flows require retries=0; uncertain submissions must be inspected before
a deliberate rerun, rather than automatically creating or approving a duplicate.

Standalone approval (one environment/license/project; no repeated approval):
  1. Set TransactionNumber in config/approvalTransacNumber.js to the exact transaction number.
  2. Run Script 3 by itself:
  npm run test -- --spec=approve --env=TEST --project=chromium
The full 01 -> 02 -> 03 flow ignores TransactionNumber and approves only the
fresh transaction captured by Script 2. Standalone Script 3 uses the configured number.

Run one standalone script with "npm run test" and a spec selection:
  npm run test -- --spec=register --env=TEST
  npm run test -- --spec=apply --env=TEST

Inspect without browser actions, credentials or approval:
  npm run conv -- --list --env=TEST
  npm run test -- --spec=approve --list --env=TEST


Main Serial Flow Commands
=========================

npm run conv
npm run conv -- --env=TEST --headed --project=chromium --repeat-each=2
npm run conv -- --env=PROD --project=chromium --repeat-each=2
npm run conv -- --env=PREPROD --headed --licenseType=COMMERCIAL
npm run conv -- --env="PRE PROD" --headed --licenseType=COMMERCIAL --parallel=3

Run selected environments concurrently with one license type:
  npm run conv -- --env=PREPROD,TEST,PROD --licenseType=RESIDENTIAL --parallel=3

Run both license types concurrently in TEST:
  npm run conv -- --env=TEST --licenseType=RESIDENTIAL,COMMERCIAL --parallel=2

Run every environment and both license types (6 combinations):
  npm run conv -- --env=ALL --licenseType=ALL --parallel=6

Endorsement Type Override Examples
==================================

Select a specific Residential endorsement:
  npm run conv -- --env="PRE PROD" --licenseType=RESIDENTIAL --ResType=ORC

Select specific Residential and Commercial endorsements in a mixed matrix:
  npm run conv -- --env=PREPROD,TEST --licenseType=RESIDENTIAL,COMMERCIAL --ResType=RC --CommType=FC --parallel=2

Select a specific Commercial endorsement:
  npm run conv -- --env=PROD --licenseType=COMMERCIAL --CommType=PASS

Random selection:
  Omit --ResType/--CommType, or leave resType/commType blank in runSettings.json.
  ResType applies only to RESIDENTIAL combinations.
  CommType applies only to COMMERCIAL combinations.

Repeat / Parallel Examples
==========================

npm run conv -- --repeat-each=2
npm run conv -- --env=TEST --repeat-each=2
npm run conv -- --env=PROD --project=chromium --repeat-each=2
npm run conv -- --env="PRE PROD" --parallel=3
npm run conv -- --env=ALL --licenseType=ALL --parallel=6

Note:
  --parallel controls how many environment/license combinations run at the same time.
  Inside every combination, Script 1 finishes before Script 2, then Script 3 starts.
  Each combination has isolated saved credentials and test artifacts.
  All combination results are merged into one HTML report, which opens once after the complete matrix finishes.

==========================

Login / Entity Name Format
==========================

Login names use this format in TEST, PRE PROD, and PROD:
  Conv_CC_12
  Conv_CC_123
  Conv_CC_1234

The first registration attempt uses 2 digits.
If the login name is taken, retry attempts use 3 digits, then 4 digits, then 5 digits, and so on.
The maximum number of attempts is controlled here:
  runSettings.json -> registrationLoginRetryLimit

Entity names use this format in TEST, PRE PROD, and PROD:
  CONV_DD-MM-YYYY_HH:MM:SS AM/PM

Example:
  CONV_25-06-2026_09:54:12 AM

Notes
=====

- "conv" runs Scripts 1, 2 and 3 in serial order. "test" requires one standalone spec.
- Environment and license-type lists create every combination. Example: 3 environments and 2 license types create 6 flows.
- ResType is applied only to Residential combinations; CommType is applied only to Commercial combinations.
- When the applicable endorsement code is blank, the framework selects randomly from its configured pool.
- Use PREPROD inside comma-separated lists. For the spaced name, quote the whole value: --env="PRE PROD,TEST,PROD".
- --parallel controls concurrent combinations; it never changes the Register -> Login/Apply -> Approve order inside a combination.
- The HTML report opens automatically after the selected run finishes.
- Use npm run report only when you want to reopen the latest report manually.
- Environment names are normalized, so PREPROD and PRE PROD both work.
- PROD existing-owner UBI is configured in editableData.js.
- Questions tab answers still avoid selecting Yes.
